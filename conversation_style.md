# Finqalab Copy & Conversation Style Guide

Reference tone: Questrade Pro ("Made to outperform"). This document adapts that voice for Finqalab — confident, fast, trader-to-trader — and defines rules for writing any Finqalab-facing copy: website sections, feature blurbs, CTAs, app copy, and marketing headlines.

## 1. Core Voice

Finqalab talks to its users like a sharp peer who respects their time and their ambition — not like a bank, not like a corporate brochure. The reader is assumed to be capable and competitive. Copy should make them feel recognized, not sold to.

**Three words that define the voice:** Confident. Fast. Personal.

- **Confident** — state claims directly. No hedging ("we aim to," "designed to help"). Say what the product does.
- **Fast** — short sentences, sentence fragments, quick rhythm. Copy should read in seconds, not require re-reading.
- **Personal** — address the user's ambition and identity ("the trader you were yesterday"), not just the feature list. Features exist to serve the user's growth, not the other way around.

## 2. What To Do

- **Open with a hook, not a description.** Lead lines should be short, declarative, and slightly provocative — a challenge or a promise, not a category label.
  - Good: "Made to outperform."
  - Weak: "Finqalab is an investment platform for Pakistani traders."

- **Use rhetorical question → confident answer** for feature callouts. This creates a hook and immediately resolves it, which reads as authority rather than hype.
  - Pattern: *"What if [surprising capability]? [Product] does."*
  - Example: "What if your portfolio rebalanced before you noticed it needed to? Ours does."

- **Use sentence fragments deliberately for feature labels and micro-headlines.** Fragments should read like punchy section titles, not incomplete thoughts.
  - Example: "Real-time settlement. No paperwork."

- **Frame the user's growth as the real subject.** Tie features back to the user beating their own past performance, not just "the market" or "competitors." This is the emotional core borrowed from Questrade's "the trader you were yesterday" line — adapt it to investing/saving context for Finqalab (e.g., "the investor you were last quarter").

- **Keep claims concrete and specific.** Prefer a number, a mechanism, or a named capability over an adjective.
  - Good: "Settle trades in real time, not T+2."
  - Weak: "Enjoy a seamless, best-in-class trading experience."

- **Let section headers do double duty as a narrative arc**, not isolated blurbs. Each header should feel like the next beat in a story about the user leveling up (discover → act → grow → trust), not a disconnected feature list.

- **Close with credibility, stated plainly.** Ratings, user counts, or regulatory trust markers — presented as fact, not exclamation.
  - Good: "Regulated by the SECP. Trusted by [N]+ investors."
  - Weak: "We're proud to be trusted by so many amazing investors!"

## 3. What To Avoid

- **No filler abstractions.** Cut phrases that could apply to any product in any category — they do no work.
  - Cut: "Personalize every pixel." / "A seamless experience." / "Built for you."
  - Keep only claims unique to Finqalab's actual mechanism.

- **No generic setup lines before proof points.** Don't preface a rating or testimonial with a throwaway line like "Highly rated for a reason." Let the number and the quote carry it.

- **No corporate hedging or passive voice.** Avoid "is designed to," "aims to help," "our platform enables users to." State the action directly: "does," "gives you," "shows you."

- **No exclamation-point enthusiasm.** Confidence reads as calm, not excited. Avoid "!" outside of rare, earned emphasis.

- **No jargon-stacking.** One sharp technical detail per line is more credible than three buzzwords together (don't chain "AI-powered, next-gen, agentic, real-time" in one breath).

- **Don't over-explain the joke/hook.** If a rhetorical-question hook is used, the answer should be one short sentence. Don't follow it with three more sentences justifying it — that kills the punch.

- **Avoid disconnected section transitions.** Don't stitch feature blurbs together with no throughline — each section should logically hand off to the next (this was a real weakness in the Questrade reference page; avoid replicating it).

## 4. Structural Patterns to Reuse

| Pattern | Use for | Example shape |
|---|---|---|
| Hook line + one-line payoff | Hero headline | "Made to outperform." / "The next-gen tools you need to beat the market — and yourself." |
| Rhetorical question → confident answer | Feature callouts | "What if X? [Product] does." |
| Fragment pairs | Micro-headlines / feature labels | "Real-time settlement. No paperwork." |
| Plain-stated proof | Trust/social proof sections | "4.8★ from 10,000+ investors. Regulated by the SECP." |
| Comparative growth framing | CTA sections, closing copy | "Beat the market. Beat who you were last quarter." |

## 5. Quick Litmus Test

Before shipping any line of Finqalab copy, ask:

1. Could this sentence appear on a competitor's site unchanged? If yes, cut or sharpen it.
2. Does it state a claim directly, or hedge? Rewrite hedges as direct statements.
3. Is it as short as it can be while staying specific? Cut words that don't add information.
4. Does it speak to the user's ambition/growth, not just the feature? If not, reframe.

## 6. Notes on Adaptation from Questrade Reference

- Questrade's audience: advanced/active traders. Finqalab's audience is broader (new + experienced Pakistani investors), so confidence should stay but the competitive edge ("beat the trader you were yesterday") should be balanced with accessibility — don't assume every reader is already an expert trader. Calibrate per page/section: acquisition-focused pages (homepage, features) can lean more aspirational; educational pages (academy, glossary) should lean more direct and instructional while keeping the same confident, jargon-light sentence rhythm.
- Avoid the reference page's weak spots directly: no "personalize every pixel"-style filler, no unearned "highly rated for a reason" transitions, and keep section-to-section flow connected rather than a stitched list of blurbs.
